# ADR-0007 — AGENTS.md 的 ADR 索引不再逐条列举编号

- 状态：Accepted
- 日期：2026-07-28
- 相关：#96

## 背景

`AGENTS.md` 的 Where to find things 一节，本项目 ADR 那一行是这样写的：

```
- `docs/adr/` — 本项目自己的决策（独立编号从 0001 起；0001 = Gate、0002 = app-download 折扣、0003 = 结账页客户端镜像、0004 = migration apply 流程）
```

写下 0005 和 0006 时，两次都忘了同步这一行。索引停在 0004。

## 问题

这不是「谁不小心」。**每加一个 ADR 就必须改一次协议文件**，而这两件事之间没有任何机制强制关联 —— 门禁不查，CI 不查，reviewer 也不会注意到。忘记是默认结果，记得才是例外。

而且这一行复制的信息，`docs/adr/` 的文件名里本来就有，而且永远是对的：文件名 = 编号 + 标题。副本会腐烂，源不会（ADR-0045 的同一条道理）。

一个已经腐烂过两次的索引比没有索引更糟：读者以为它是全的，于是不去看目录。

## 决策

**索引只指路，不列目录内容。** 改成：

```
- `docs/adr/` — 本项目自己的决策（独立编号从 0001 起，编号与标题见目录内文件名）
```

同一条理由适用于 `docs/gearbox-adr/` 那一行的编号范围（`0001~0049`），它同样会随 gearbox 回填而腐烂 —— 一并去掉具体数字。

判据：**协议文件里不写任何「目录里 ls 一下就能得到、且会随目录增长而变化」的东西。** 稳定的语义（这个目录放什么、谁能改、怎么编号）继续写。

## 后果

- 想知道有哪些 ADR，得看一眼 `docs/adr/`。这是目的：那里的答案永远是对的。
- 索引不再需要跟着 ADR 一起改，少一个必然会被遗忘的义务。
- 代价：`AGENTS.md` 单文件不再能一眼看全决策清单。可接受 —— 它本来也做不到，只是看起来像做到了。

## 分级

L2（改索引，ADR-0005 的映射表）。本 ADR 不引用 L1/L2 机制以外的任何东西，也不新增义务 —— 它取消了一个。

## 什么情况下该推翻

如果出现某个消费者（比如某个工具或 agent 流程）只读 `AGENTS.md`、拿不到目录列表，那它需要的是一个生成步骤，不是手工维护的副本。届时加生成，别加回手写清单。
