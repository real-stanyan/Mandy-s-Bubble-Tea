SMS OTP Architecture

Overall data flow and components

Authentication Flow
User enters phone number
↓
POST /api/auth/send-code
↓
Generate 6-digit OTP Store in Upstash Redis (TTL 5min) Twilio SMS send
↓
User enters 6-digit code
↓
POST /api/auth/verify-code
↓
Check OTP match Delete OTP from Redis Generate deviceToken (UUID)
↓
Store deviceToken → phone mapping in Redis (no TTL)
↓
Frontend stores deviceToken in localStorage
↓
Subsequent visits: POST /api/auth/check-token
↓
Redis lookup: deviceToken → phone → auto-login

New API Routes

POST /api/auth/send-code Accepts phone, generates OTP, stores in Redis, sends via Twilio
POST /api/auth/verify-code Accepts phone + code, verifies, returns deviceToken
POST /api/auth/check-token Accepts deviceToken, returns phone if valid (for auto-login)

New Dependencies

twilio SMS sending
@upstash/redis Serverless Redis for OTP + deviceToken storage (free tier: 10K cmd/day)

New Env Vars

TWILIO_ACCOUNT_SID Twilio account
TWILIO_AUTH_TOKEN Twilio auth
TWILIO_PHONE_NUMBER Sender number (AU or toll-free)
UPSTASH_REDIS_REST_URL Upstash REST endpoint
UPSTASH_REDIS_REST_TOKEN Upstash auth token
